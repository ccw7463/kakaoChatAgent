# 01. 진단

마지막 커밋이 2025-01-18. 약 1년 7개월 방치된 상태였다.
서로 다른 세 개 층에서 동시에 죽어 있었다.

## 1층 — 프로세스가 뜨지 않음

### `.env` 부재로 import 시점 크래시

```
utils/util.py:22  os.environ["OPENAI_API_KEY"] = os.getenv("OPENAI_API_KEY")
TypeError: str expected, not NoneType
```

`modules/__init__.py`에서 `set_env()`를 무조건 호출해, `.env`가 없으면 첫 줄에서 죽었다.
그런데 **README에 `.env`나 API 키에 대한 언급이 한 줄도 없었다.** `.env.example`도 없었다.
클론한 사람은 무조건 여기서 막힌다.

### 실행 환경 부재

- poetry 미설치, `.venv` 없음
- 시스템 파이썬 3.9.6 (프로젝트는 `^3.11` 요구)
- Playwright 브라우저 바이너리 미설치 — README에 `playwright install` 단계가 없었다

## 2층 — 카카오와의 연결선 단절

`app.py:44`에 ngrok 주소가 하드코딩되어 있었다.

```python
webhook_url="https://changwoo.ngrok.dev/webhook"
```

해당 주소로 POST 하면 ngrok의 "tunnel not found" 페이지(HTTP 404)가 돌아왔다.
머신에 ngrok이 설치되어 있지도 않았다. 카카오 오픈빌더의 스킬 서버 URL도 같은 도메인
기반이었으므로 인입 경로도 함께 죽어 있었다.

> 카카오 정책 자체는 문제가 없었다. 챗봇은 2022년부터 무료 전환되었고 콜백 스펙도 유지 중이다.
> 막힌 것은 카카오가 아니라 이쪽 인프라였다.

## 3층 — 웹 검색 완전 파손 (체감상 주범)

Playwright를 실제로 실행해 확인했다.

```
에러 발생: Page.type: Timeout 30000ms exceeded.
  - waiting for locator("#APjFqb")
FAILED: Exception 검색 실패
```

에러 스크린샷을 열어보니 구글 홈이 개편되어 있었다. 검색창에 'AI 모드' 버튼이 붙은
새 레이아웃이고 `#APjFqb` id가 사라졌다. 결과 파싱용 `div.yuRUbf` / `h3.LC20lb`도 스테일.

**조용히 실패하지 않는다는 점이 더 문제였다.**

- `_web_search()`에서 예외 발생 → `get_answer()`에 try/except 없음 → 백그라운드 태스크 사망
- → `send_to_webhook()`이 호출되지 않음 → **사용자는 카톡에서 영영 응답을 못 받음**

즉 "최신 정보" 성격의 질문은 100% 무응답이었다.

`modules/agent.py:293,300`의 맨몸 `except: pass`가 문제를 가렸다. 첫 `except: pass` 후
`detailed_content`가 미정의인 채 다음 `try`로 진입하고, 거기서 나는 `NameError`를 또 삼켜
결과가 조용히 누락됐다.

## 구조적 결함

| 문제 | 위치 |
|---|---|
| **이벤트 루프 블로킹.** `get_response`는 `async`인데 속은 동기 `graph.invoke()`. 한 명이 답변 생성 중이면 다른 사용자는 카카오 5초 제한을 넘겨 끊긴다 | `agent.py:21`, `app.py:76` |
| `queue.get()` 타임아웃 없음. 자식 프로세스 하드 크래시 시 영구 행 | `util.py:143` |
| 콜백 URL은 유효 1분/1회용인데 LLM을 5~6회 호출 | 설계 전반 |
| `user_agents` dict 무한 증가 (메모리 릭) | `app.py:12` |
