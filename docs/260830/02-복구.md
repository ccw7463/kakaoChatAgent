# 02. 복구

동작 불능 상태를 걷어낸 작업. 커밋 `79b94ba`.

## 웹 검색: 구글 스크래핑 → Tavily API

셀렉터를 고쳐봐야 구글이 다시 바꾸면 똑같이 깨진다. 검색 API로 교체했다.

- Playwright, 멀티프로세싱, `extract_content` 전부 제거
- Tavily가 검색과 본문 추출을 함께 처리하므로 별도 스크래핑이 불필요
- 죽은 주석 코드 176줄(이전 스크래퍼 3종) 정리
- 부수 효과로 `queue.get()` 영구 행 문제도 함께 소멸

검색 실패 시 예외를 던지지 않고 **빈 결과를 반환**하도록 바꿔, 호출측이 검색 없이
일반 답변으로 폴백한다. `except: pass` 두 개도 제거했다.

## 무한 대기 제거

```python
try:
    response = await _generate_response(agent, question, START_TIME)
except Exception as e:
    print(...)
    response = FALLBACK_MESSAGE      # 실패해도 반드시 콜백 전송
await send_to_webhook(...)
```

`callbackUrl`이 없는 경우(오픈빌더 콜백 미설정)도 즉시 안내 응답을 반환하도록 했다.
예전에는 이 경우에도 사용자가 무한 대기했다.

## 이벤트 루프 블로킹 해결

`graph.invoke()`는 동기인데 `async` 함수에서 직접 호출하고 있었다.

```python
result = await asyncio.to_thread(self._call_graph, [question])
```

`webhook_handler`의 동기 `requests.post`도 `httpx.AsyncClient`로 교체했다.

### 측정

8초짜리 실제 블로킹 작업을 돌리면서 다른 사용자의 요청 응답시간을 쟀다.

| | 응답시간 | 카카오 5초 제한 |
|---|---|---|
| 수정 전 | **7.51초** | 초과 (연결 끊김) |
| 수정 후 | **0.01초** | 통과 |

## 부수적으로 발견해 고친 것

`generate_search_keyword` 프롬프트가 f-string이라 `datetime.now()`가 **모듈 import
시점에 한 번만 평가**됐다. 장기 실행 서버에서 "오늘 날짜"가 서버 기동일에 영원히
고정된다. 런타임 계산으로 바꿨다.

## 검증

| 검증 | 결과 |
|---|---|
| `.env` 없을 때 | `TypeError` → 명확한 한글 안내 |
| 검색 실패 시 | 무응답 → 일반 답변 폴백, 콜백 정상 |
| 답변 생성 예외 | 무한 대기 → 폴백 메시지 수신 |
| `callbackUrl` 없음 | 무한 대기 → 즉시 안내 |
| 동시 사용자 | 7.51초 → 0.01초 |

가짜 카카오 서버를 띄우고 `POST /question`을 보내 콜백 도착까지 확인했다.
