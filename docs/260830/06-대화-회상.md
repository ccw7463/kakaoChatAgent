# 06. 과거 대화 회상 (pgvector)

커밋 `09426cc`.

## 문제

대화 이력은 최근 12개만 유지되고, 그 이전 내용은 완전히 소실됐다.
"아까 말한 그거" 류의 질문에 답할 수 없었다.

## 구조

```
질문 → [라우팅 x3 + 회상] 병렬 → 검색 → 답변 → 콜백 전송
                                            ↓ (사용자 대기 없음)
                                     메모리 갱신 + 대화 임베딩 저장
```

회상 노드가 라우팅과 병렬 실행되어 **추가 지연이 사실상 없다**
(검색 경로 8.1 → 7.6초).

## 임베딩

OpenRouter `/embeddings`의 `google/gemini-embedding-001` (3072차원).
langchain `OpenAIEmbeddings` 대신 `httpx`로 직접 호출한다. tiktoken 기반 사전 절단이
한국어에서 엉뚱한 자리를 끊고, 응답의 usage/비용 정보도 버려지기 때문이다.

## 3072차원 색인 문제 해결

pgvector의 `vector` 타입은 **인덱스 차원 상한이 2000**이라 3072차원을 색인할 수 없다.
그대로 두면 전수 스캔이 된다.

**`halfvec` 타입은 4096차원까지 색인 가능**하다 (pgvector 0.7+, Supabase는 0.8.0).

```sql
CREATE TABLE kakao_agent.conversations (
    id BIGSERIAL PRIMARY KEY,
    user_id TEXT NOT NULL,
    question TEXT NOT NULL,
    answer TEXT NOT NULL,
    embedding halfvec(3072) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ... USING hnsw (embedding halfvec_cosine_ops);
```

## 유사도 임계값 — 두 번 틀렸다

### 1차 시도: 0.72 (틀림)

합성 샘플로 측정해 0.72를 잡았으나 실사용에서 맞지 않았다.

```
"우리 강아지 몇 살이었지?" ↔ 강아지 대화    0.686   ← 못 넘음
"고마워!" ↔ "고마워"                      0.741   ← 쓸모없는데 통과
```

그때 정답이 나온 것은 회상이 아니라 `personal_info` 메모리 덕이었다.
**성급하게 "된다"고 판단했던 것을 측정으로 바로잡았다.**

### 원인: 인사말 오염

인사말끼리는 유사도가 0.8을 넘어 정작 유용한 회상을 밀어냈다.
저장 방식(Q+A / Q만 / A만)도 비교했는데, 인사말 쌍을 제외하면:

| 저장 방식 | 관련 최저 | 무관 최고 | 간격 |
|---|---|---|---|
| **Q+A (현재)** | **0.707** | 0.607 | **+0.100** |
| Q만 | 0.722 | 0.639 | +0.083 |
| A만 | 0.669 | 0.598 | +0.071 |

현재 방식이 가장 좋았고, 문제는 저장 방식이 아니라 **무엇을 저장하는가**였다.

### 최종: 6자 미만 미저장 + 임계값 0.66

인사말("고마워" 3자, "잘가" 2자)을 저장하지 않으니 분리가 깨끗해졌다.

> 6자 기준은 휴리스틱이다. "서울 인구는"(6자)은 살아남지만 그보다 짧은 진짜 질문은
> 저장되지 않는다.

## 검증

`personal_info` 개입을 배제하기 위해 **개인정보가 아닌 사실**로 테스트했다.

```
[1] "파이썬에서 리스트를 정렬하는 방법 알려줘" 저장
[2] 필러 6턴으로 대화창(12개)에서 밀어냄
[3] "아까 리스트 정렬 뭐라고 했지?" → 회상 성공
    "고마워!" / "로또 번호 추천해줘" / "너 누구야" → 회상 없음 (정상)
```

프로덕션에서도 동일하게 검증했다. `personal_info`에 딕셔너리·정렬 관련 내용이 전혀
없는(선호도만 저장된) 상태에서 대화창에서 밀려난 답변을 정확히 재현했다.

## 안전장치

임베딩 실패 · 조회 실패 · **pgvector 미지원** 중 무엇이 발생해도 회상만 비활성화되고
답변은 정상 진행한다.

> 검증 중 발견한 문제다. 원래는 pgvector가 없으면 `_initialize_db`가 실패해
> **봇 전체가 뜨지 않았다.** pgvector 없는 순정 Postgres와 있는 환경 양쪽에서 확인했다.

## 설정

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `EMBED_MODEL` | `google/gemini-embedding-001` | 임베딩 모델 |
| `RECALL_LIMIT` | 3 | 회상 최대 건수 |
| `RECALL_MIN_SIMILARITY` | 0.66 | 유사도 하한 |
| `RECALL_MIN_QUESTION_CHARS` | 6 | 이보다 짧은 질문은 미저장 |
