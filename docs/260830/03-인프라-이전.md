# 03. 인프라 이전

## poetry → uv

커밋 `fb541b0`.

- `pyproject.toml`을 PEP 621 표준 형식으로 재작성 (`[project]` + `[dependency-groups]`)
- `poetry.lock` 제거, `uv.lock` 생성, `.python-version`으로 3.11 고정
- 사용하지 않던 selenium / playwright / bs4 / html2text / langchain-community 제거

```bash
uv sync && uv run python app.py    # 이게 전부
```

### 빗나간 가설 — 이미 langgraph 1.x였다

"의존성이 langgraph 0.2 세대에 고정되어 있어 현행화 필요"라고 판단했으나 **틀렸다.**
실제 설치 버전을 확인해보니:

```
langgraph          1.2.11   (최신)
langchain-core     1.6.1    (최신)
langchain-openai   1.6.0    (최신)
```

poetry의 `^0.2.60`(상한 있음)이 uv의 `>=0.2.60`(상한 없음)으로 바뀌면서, uv 전환
시점에 이미 최신으로 해석되어 있었다. 프로덕션 검증도 처음부터 1.x 위에서 돌고 있었다.
`pyproject.toml`의 **하한값만 보고 판단한 오류**였다.

그래서 실제 작업은 마이그레이션이 아니라 **선언 정리**가 되었다. 커밋 `81df5a3`.

- 하한을 실제 검증된 버전으로 조정 (`langgraph>=1.2.11` 등)
- 직접 import 하는 `langchain-core`를 명시 선언 (누락되어 있었음)
- 선언만 되고 안 쓰이던 `loguru` 제거, `openai`는 전이 의존성으로 강등

그럼에도 langgraph 1.x에서 실제로 도는지 전수 재검증했다. 팬아웃/팬인, 체크포인터,
`InMemoryStore`, `RemoveMessage`, HTTP 흐름, 동시성, 실제 LLM/검색/DB 왕복,
Docker `uv sync --frozen` 모두 통과.

## sqlite → Supabase

커밋 `79b94ba`.

`modules/db.py`를 psycopg3 + 커넥션 풀로 재작성했다.

### 전용 스키마 격리

기존 개인 프로젝트(`mystudio`)의 Supabase를 재사용하기로 해서, 테이블을 `public`이
아닌 **전용 스키마 `kakao_agent`** 에 만들었다. 두 가지가 보장된다.

1. 기존 `public.users` 등과 이름이 충돌하지 않는다
2. **Supabase는 `public` 스키마만 PostgREST로 공개**하므로, 개인정보 테이블이
   anon 키로 외부에서 조회되지 않는다

검증을 위해 `public.users`에 기존 데이터를 미리 넣어두고 앱을 돌렸다. 기존 테이블은
손대지 않았고 카톡 데이터는 별도 스키마에 들어갔다.

스키마명은 파라미터 바인딩이 불가능한 자리라 식별자 형식 검증을 넣었다.
`public; DROP SCHEMA ...` 등 4가지 케이스 차단 확인.

### 무료 플랜 일시정지 대응

Supabase 무료 플랜은 **7일간 쿼리가 없으면 프로젝트를 자동 일시정지**한다.
앱이 12시간마다 `SELECT 1`을 보내는 keepalive를 lifespan에 추가했다.

> 부수 효과로 같은 프로젝트를 쓰는 다른 앱도 함께 잠들지 않게 되었다.

### 연결 방식

`SUPABASE_URL` + `SECRET_KEY`(PostgREST) 대신 `DATABASE_URL`(Postgres 직결)을 택했다.

| | PostgREST | 직결 (선택) |
|---|---|---|
| 테이블 생성 | 불가 (DDL 미지원) | 자동 |
| 스키마 | 노출된 스키마만 | 제한 없음 |

서버 사이드 백엔드라 직결이 자연스럽고, 스키마·테이블 자동 생성으로 마이그레이션이
필요 없어진다.

## OpenAI → OpenRouter

커밋 `79b94ba`.

`ChatOpenAI`의 `base_url`만 OpenRouter로 돌렸다. OpenAI 호환 API라 langchain 코드는
그대로 쓴다. 모델은 `LLM_MODEL` 환경변수로 분리했다.

```python
self.llm = ChatOpenAI(
    model=LLM_MODEL,                      # google/gemini-3-flash-preview
    base_url="https://openrouter.ai/api/v1",
    api_key=os.getenv("OPENROUTER_API_KEY"),
)
```

### 모델 교체 시 터졌을 버그

기존 라우팅은 `content.upper() == "YES"` **정확 일치**만 인정했다. gpt-4o에 맞춰진
코드라, 모델마다 `"YES."` / `"**YES**"` / `"Yes, 필요합니다"` 로 답하면
**웹 검색과 메모리 저장이 조용히 전부 걸리지 않았을 것이다.**

알파벳만 남겨 판정하는 `_parse_yes_no()`를 추가하고 14개 케이스로 검증했다
(`'아니요, NOT needed'` → NO 같은 함정 포함).
