# 04. 배포 (ngrok → Railway)

커밋 `067d0d7`, `a77d6ec`, `26995b6`.

## 왜 Vercel이 아닌가

이 앱은 카카오에 `useCallback:true`를 먼저 응답하고, **응답 이후에** 백그라운드에서
답변을 만들어 콜백을 친다. Vercel 서버리스는 응답을 보내면 함수를 종료시키므로
이 구조가 성립하지 않는다. `user_agents` / `MemorySaver` 같은 인메모리 상태도 유지되지
않는다. 프로세스가 계속 사는 환경이 필요하다.

무료 플랜 중 15분 미사용 시 잠드는 유형(Render 무료 등)도 부적합하다. 깨우는 데
30~60초가 걸려 **카카오 5초 제한을 넘겨 첫 메시지가 무조건 실패**한다.

## 구성

- `Dockerfile` — uv 공식 이미지 기반, `uv sync --frozen`으로 재현 가능한 빌드
- `railway.json` — Dockerfile 빌더, `/health` 헬스체크
- `.dockerignore`
- `PORT` 환경변수 대응 (Railway가 주입), `/health` 엔드포인트 추가

`WEBHOOK_URL` 기본값을 루프백으로 바꿔, 서버가 자기 자신을 공인 인터넷으로 왕복하지
않게 했다. (기존에는 하드코딩된 ngrok 공인 주소로 나갔다 돌아왔다)

## 리전

기본값이 `us-west2`(미국 서부)로 잡혀, 카카오(한국)와 Supabase(서울) 양쪽에서 멀었다.
`southeast-asia`로 이전했다.

```bash
railway service scale --service kakao-agent southeast-asia=1 us-west=0
```

| | US West | Southeast Asia |
|---|---|---|
| 1차 응답 | 2.0초 | **0.95초** |

## 자동 배포

`railway service source connect --repo ccw7463/kakao-agent --branch main`

`main` 푸시 → **15~21초** 만에 배포 완료. 실제 푸시로 트리거되는 것까지 확인했다.

## Config as Code 지원 종료

`railway.json`은 **2026-12-01까지만** 지원된다. 새 IaC 형식(`.railway/railway.ts`)으로
마이그레이션을 시도했으나 **npm 패키지(`railway`) 설치가 필요해** Python 저장소에
node_modules를 들이는 것은 과하다고 판단하고 되돌렸다. 기한을 `railway.json` 주석에
남겨두었다.

## 검증

가짜 카카오 서버를 만들어 공개 URL에 실제 형식의 요청을 보냈다.

| 항목 | 결과 |
|---|---|
| `/health` | `{"status":"ok"}` |
| `/question` 즉시 응답 | **0.95초** (제한 5초) |
| 콜백 도착 | **13~22초** (제한 60초) |
| `callbackUrl` 없는 경우 | 즉시 안내 응답 |

더미 키로 OpenAI 401을 유도했을 때도 **폴백 메시지가 콜백으로 정확히 도착**했다.
예전 코드였으면 무한 대기였을 상황이다.

## 카카오 연결

챗봇 관리자센터에서 스킬 `send_question`의 URL을 교체했다.

```
https://kakao-agent-production.up.railway.app/question
```

기존 스킬 목록에 `get_answer`, `카톡챗봇답변`이 있었으나 **적용 블록수 0**이라
미사용 잔재였다. `send_question`(적용 블록수 1)만 수정 대상이었다.

> 블록의 **콜백 사용** 옵션이 켜져 있어야 하고, 수정 후 **배포**를 눌러야 반영된다.

## 배포 중 짧은 공백

새 컨테이너로 전환되는 몇 초 사이 502가 발생할 수 있다. 배포 중 들어온 메시지 한 건은
실패할 수 있다. 개인 봇 수준에서는 무중단 구성까지는 불필요하다고 판단했다.
