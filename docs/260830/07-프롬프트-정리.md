## 정리하면서 발견한 버그 3건

### 1. 호칭 오인

시스템 프롬프트의 `'ccw'님에 의해 개발되었습니다`를 모델이 사용자 이름으로 오인해,
이름을 모르는 사용자를 **"ccw님"** 이라고 불렀다.

개발자 언급을 제거하고 *"사용자의 이름을 모르면 지어내지 말고 호칭 없이 존댓말로
답하세요"* 를 명시했다.

### 2. 선호도에 신상정보 유출

```
- 사용자는 서울에 거주하며 직업은 개발자이다.   ← 선호도가 아님
```

선호도는 **답변의 형식과 말투**에 대한 것만 기록하도록 경계를 명시했다. 수정 후:

```
- 사용자는 이모지를 사용하지 않는 것을 선호한다.
- 사용자는 짧게 대답하는 형식을 선호한다.
```

### 3. 라우팅 판단 기준 누락 (재작성 중 만든 회귀)

재작성하면서 *"현재 요청문 기준"* 이라는 문구를 빼먹었다. 라우팅 프롬프트에는
대화창의 이전 요청이 모두 함께 들어가는데 기준이 없으니, 과거 메시지의 선호 표현에
반응했다 (`"고마워!"` → preference=YES).

`[현재 요청 메시지]` 기준으로 판단하도록 명시하니 **라우팅 5종 전부 정확**해졌다.
부수적으로 "앞으로 더 짧게 대답해줘"의 personal 오탐도 사라졌다.

## 제거한 군더더기

- `system_message`와 `answer_prompt`가 **"당신은 챗봇입니다"를 중복 선언**
- 선호도 **판단**(YES/NO)에 예시 10개 나열 — 추출 프롬프트에만 두면 충분
- 메모리 프롬프트의 지침 6·7·8이 **같은 말 세 번**
- completion 모델 시절 잔재인 `답변:` 꼬리표

## 개인화 블록 조건부 조립

저장된 정보가 없어도 `[사용자 정보]:` 빈 헤더가 들어가고 있었다. 토큰만 쓰고 모델을
헷갈리게 한다. 내용이 있을 때만 붙이도록 `_build_system_message()`를 만들었다.
